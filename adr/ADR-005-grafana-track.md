# ADR-005 — Partner track: Grafana (observability as governance)

**Status:** Superseded by [ADR-008](ADR-008-grafana-mcp-qualifying-use.md) · 2026-08-02 (Amended 2026-08-03)

## Context
Five partner tracks (IBM, Grafana, Parallel, ClickHouse, Replit); projects compete only
within their track; partner usage must be at runtime, called from code.

## Decision
**Grafana Cloud.** (a) OpenTelemetry traces/metrics from every agent, MCP server and
the solver, exported via OTLP; (b) the Conflict Sentinel calls the **Grafana
Annotations API from code** on every anomaly; (c) alerting rules on
`anomaly.severity = critical`; (d) the "Shoot Mission Control" dashboard is provisioned
via API from versioned JSON in the repository.

Rejected: ClickHouse (small data volume, forced fit), Replit (conflicts with the .NET
stack), IBM watsonx (a second agent platform, redundant with Gemini), Parallel (would
only fit a location-scouting agent outside the MVP).

## Consequences
- Observability is foundation-level infrastructure (from the first increment), not a
  bolt-on.
- Differentiator within the track: telemetry *generated by the agents themselves*.
